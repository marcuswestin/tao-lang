# Merge Feature Branch

## Overview

Land the current feature branch into `main` with the Tao repo's supported `./agent` command surface. Preserve user work, keep the branch green, and use a squash commit message that retains Git's autogenerated squashed-commit details.

## Required Rules

- Use `./agent help` first if it has not already run in the session.
- Use `./agent git ...` for every Git command and `./agent prep-commit` before every commit-creating action.
- Do not land from `main`, a detached HEAD, or a dirty working tree.
- Do not include unrelated local changes in the merge. If the branch is dirty, stop and use `skills/git-workflow/SKILL.md` or `skills/commit-all-chunks/SKILL.md` first.
- Do not delete the feature branch unless the user explicitly asks.

## Workflow

1. Identify the feature branch and inspect state:

   ```sh
   ./agent git status --short --branch
   ./agent git branch --show-current
   ```

   Stop if the current branch is `main`, empty, detached, or has uncommitted changes.

2. Run prep on the feature branch:

   ```sh
   ./agent prep-commit
   ```

   Fix failures before continuing. If fixes are needed, commit them through `skills/git-workflow/SKILL.md`.

3. Ensure the feature branch is committed and pushed:

   ```sh
   ./agent git push -u origin HEAD
   ./agent git status --short --branch
   ```

   Continue only when the status no longer reports unpushed local commits.

4. Refresh local `main`, then merge local `main` into the feature branch:

   ```sh
   ./agent git checkout main
   ./agent git fetch origin main
   ./agent git merge --ff-only origin/main
   ./agent git checkout <feature-branch>
   ./agent prep-commit
   ./agent git merge --no-edit main
   ```

   Do not merge `origin/main` directly into the feature branch. Always update local `main` first, then merge local `main` so the feature branch is tested against the same `main` that will receive the squash commit.

   If there are conflicts, resolve them directly, stage the resolved files, run `./agent prep-commit`, then complete the merge commit with `./agent git commit`. After any merge commit, run `./agent prep-commit` again.

5. Push the updated feature branch:

   ```sh
   ./agent git push -u origin HEAD
   ```

6. Switch to `main`, verify it is current, and squash the feature branch:

   ```sh
   ./agent git checkout main
   ./agent git fetch origin main
   ./agent git merge --ff-only origin/main
   ./agent git merge --squash <feature-branch>
   ```

   If local `main` advances here, do not squash yet. Return to step 4, merge the refreshed local `main` into the feature branch, validate, push the feature branch, then come back to this step.

7. Create the squash commit message from Git's generated squash message:

   - Inspect Git's autogenerated squash message with `./agent cat .git/SQUASH_MSG`.
   - Keep the autogenerated squashed commit details below the custom summary. Do not replace them with a hand-written list.
   - At the top of the message, add:
     1. A first line summary in Tao commit style, for example `feat(scope): land <feature>`.
     2. A blank line.
     3. A concise bullet list of the main changes made.
     4. A blank line.
     5. The original generated squash body, starting with Git's squashed-commit heading and including the commit messages for every squashed commit.

   The final shape should be:

   ```text
   feat(scope): land feature name

   - Main change one
   - Main change two
   - Main change three

   Squashed commit of the following:

   <Git-generated commit details and commit messages>
   ```

8. Before creating the squash commit, run:

   ```sh
   ./agent prep-commit
   ```

   Then commit using the prepared multi-line message. Prefer an editor or message file so the autogenerated squash body is preserved; do not use a single `-m` line.

9. Validate and push `main`:

   ```sh
   ./agent prep-commit
   ./agent git status --short --branch
   ./agent git push origin main
   ```

## Handoff

Report the landed feature branch, the final squash commit hash, whether `main` was pushed, and any validation failures or conflict resolutions.
